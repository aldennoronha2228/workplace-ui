# Runtime instrument integration

Owned implementation: `src/hardware/runtime.ts` and `src/components/hardware-instruments.tsx` / `.css`. Mount named/default `HardwareInstruments` with `{ runtime: HardwareRuntime | null, results: RuntimeResults | null, analogResult?: AnalogSolveResult | null }`. The parent supplies the actual runtime instance, its existing result callback, and optionally the separate SPICE worker result. No new runtime instance is created by the panel.

Runtime API remains `connect`, `registerElement`, `results`, `sendSerial`, `dispose`. Public `run(project, artifact)` and `stop()` also permit direct integration/testing. `subscribeInstrumentation(listener)` returns an unsubscribe function; listeners receive an `InstrumentationSnapshot` on initial subscription and on the 150 ms runtime publication cadence, clear, run, and stop. Digital edges are captured synchronously from the owned vendor simulator's `onPinChangeWithTime`; an existing callback is chained, not discarded.

- `DigitalSample`: `{ pin: string, level: boolean, time_ms: number, cycles: number }`. Canonical channel labels are D0-D13/A0-A5 for Uno/Nano, D0-D53/A0-A15 for Mega, GP0-GP29 for Pico. Nano A6/A7 are analog-only and excluded from digital channels. Pico non-header pins are explicitly identified; GP25 is its onboard LED.
- `getSamples(pin?, sinceMs?)` returns a chronological copied array from an 8192-edge bounded ring. `readChannel(pin)` returns `{ pin, level: boolean | null, drive: string }` from the actual PinManager. `getChannels()` lists selectable channels. Unknown/unobserved levels stay null; no artificial baseline is injected.
- `getInstrumentation()` returns `{ board, artifact_id, clock_hz, simulated_ms, capacity, dropped_samples, samples, channels }`. `clearSamples()` clears capture history and overrun count without resetting firmware or serial. `results()` retains existing fields and adds optional `board`, `clock_hz`, `samples` (most recent 256 real edges), `sample_capacity`, and `dropped_samples`; command read/stop/run acknowledgements include these recent samples.
- Pause freezes the panel's view only; firmware and bounded capture continue. Clear resumes the live view and clears digital history. Time scale is milliseconds per division across ten divisions. SVG step traces only extend observed states; unknown history is blank. Default selection is D13 (GP25 on Pico). Multiple channels can be added/removed.
- Optional analogResult uses the SPICE contract's actual transient time in seconds and nodeVoltages; DC results are displayed as numerical readings, never invented time traces. Failed solves show diagnostics. Analog capture is not electrically coupled into MCU GPIO/ADC here and has its own solver time origin; parent owns solving and revision freshness.

Supported artifacts require matching board/source/project revisions. AVR uses validated Intel HEX `hex` (or canonical `program` text). Pico uses `format: "bin"`, `encoding: "base64"`, `load_address: 268435456`, `size_bytes`, and base64 `program` (legacy backend `bin` accepted while migration is underway). Conflicting populated program/legacy payloads are rejected. Unsupported boards/formats and malformed binaries return actual errors, not successful acknowledgements. Pico uses vendor loadBinary(base64), getClockHz() (125 MHz), real cycle count, and UART0 terminal; USB CDC, second-core execution, and Pico W radio are not implemented. AVR runs at the vendor's 16 MHz. Only digital LED continuity and rail-connected pushbuttons have attached component behavior; other parts are placement-only unless separately integrated.
