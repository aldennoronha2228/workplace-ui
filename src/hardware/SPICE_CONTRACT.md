# Analog integration contract

Owned files: `src/hardware/spice.ts`, its typed `spice-netlist.js`/`.d.ts` upstream bridge, `src/components/schematic-canvas.tsx`, `src/components/schematic-canvas.css`, `tests/spice.spec.ts`, and this contract. The bridge preserves direct upstream runtime reuse without pulling existing vendor-only TypeScript errors into the application type-check. Backend, runtime, workspace, and oscilloscope are not edited here.

- Import `sourceCatalog` from `src/hardware/spice.ts`. Entries use canonical catalog fields (`type`, `name`, `category`, `pins`, `defaultValues`, `properties`, `simulation_supported`). Parent should mirror these definitions into the backend catalog. Types: `voltage-source`, `current-source`, `sine-source`, `pulse-source`, `ac-source`, `pwl-source`, `ground`, `analog-resistor`, `analog-capacitor`, `analog-inductor`. Source pins are `+` and `-`; ground has `GND`; analog passives have `A` and `B`. Existing `resistor`, `capacitor`, `inductor` types with `1`/`2` are also supported.
- All numerical parameters accept finite numbers or strict SPICE engineering strings (`1k`, `10u`, `1Meg`). `m`/`M` means milli; use `Meg` for mega. Invalid values are errors, not silently replaced with defaults. Missing values use catalog defaults.
- `solveAnalog(project, options?)` returns a Promise of `AnalogSolveResult`. Options: `analysis: 'dc' | 'transient'` (default DC), `step` (default `10u`), `stop` (default `10m`), `timeoutMs` (default 30000). No project mutation or backend calls.
- Result: `ok`, `analysis`, `projectRevision`, `netlist`, `diagnostics` (`severity`, `message`, optional `componentId`), `time: number[]` (seconds, empty for DC), `nodeVoltages: Record<net, number[]>`, `branchCurrents: Record<ngspice-source-name, number[]>`, `componentCurrents: Record<canonical-component-id, number[]>`, `pinNetMap: Record<'component:pin', net>`, `solveMs`. DC arrays have one sample; transient vectors align with the real ngspice time axis. Current sign is from the first pin (`+`/`A`/`1`) toward the second. Failed solves have no measurement arrays. No synthetic waveform interpolation or fallback solver.
- `buildAnalogNetlist(project, options?)` is exported for validation/testing, returning `netlist`, `pinNetMap`, `nets`, `currentVectors` (component ID to source name), `analysis`, and `diagnostics`. It throws `AnalogValidationError` with structured diagnostics on invalid input. Unsupported isolated components are reported and omitted; wires involving unsupported components are rejected rather than pretending to simulate MCU pins.
- Import named/default `SchematicCanvas` and pass `{ project, selectedId?, onSelect?, onMove?, onConnect?, result?, catalog? }`. `onSelect(id)` selects a canonical component. Optional `onMove(id, x, y)` commits a drag; optional `onConnect(from, to)` commits a two-pin click connection with canonical endpoints. Without these callbacks the view is read-only except selection. Canonical controls remain the editing authority. The view is explicitly a flat 2D schematic and never auto-solves. Pass `result` to display actual diagnostics and node readings; revision-mismatched readings are marked stale.
- Sources: voltage `voltage: 5`; current `current: '1m'`; sine `offset: 0, amplitude: 5, frequency: 1000, delay: 0, damping: 0, phase: 0`; pulse `low: 0, high: 5, delay: 0, rise: '1u', fall: '1u', width: '500u', period: '1m'`; AC `voltage: 0, magnitude: 1, phase: 0`; PWL `points: [[0, 0], ['1m', 5], ['2m', 0]]`. AC source DC/transient values come from `voltage`; its small-signal magnitude/phase are included in the deck but AC frequency analysis is not part of this initial solve API. Passive property `value`: resistor `1k`, capacitor `1u`, inductor `1m`.
- Browser tests are in `tests/spice.spec.ts`: real 5 V divider → 2.5 V and 2.5 mA, strict engineering-value validation, floating rejection, actual ngspice conflicting-source singular failure, real pulse transient, and schematic selection/connect/drag. Optional `SPICE_BASE_URL` points these tests at an isolated Vite target. Screenshot: `test-results/spice-schematic.png`. An explicit production solver-entry build confirmed `ngspice-interactive-worker-*.js` emission.
- Requires existing `/wasm/ngspice-interactive/ngspice-lib.js`, `.wasm`, `spinit`, and code-model assets. Vite emits the upstream classic worker from its vendored URL. Browser engine is the genuine Velxio `NgSpiceWorkerAdapter`/`NgSpiceInteractive`; connectivity and passive cards reuse `buildNetlist`. No tools, credentials, or runtime tokens are read.
